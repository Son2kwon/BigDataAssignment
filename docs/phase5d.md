## 5d.1 준비 실험 경로 (구현, 실행 전)

### 한 일

- `04g_m1_thought.py`에 train 전용 입력, 모든 N/fold의 진단·어휘 준비, t∈{10,30,100} × 어휘 K∈{10,20}의 6조합 OOF 탐색 경로를 작성했다.
- 진단은 t∈{5,10,20,30,50,100}에서 후보 수, 단일 저장소 집중 비율, 이슈 본문 겹침 비율과 분자·분모를 기록한다. 라벨을 받지 않는 `thought.occurrences`와 라벨을 받는 `thought.association`을 분리했다.
- OOF fold마다 어휘를 독립적으로 고르고, 같은 어휘의 numpy 행렬을 XGB 설정·B1 유무·최종 묶음에서 재사용한다. 모든 N의 후보 수를 확인한 뒤에만 GPU 점검·모델 학습에 들어간다.

### 결정과 근거 (기각한 안 포함)

- `[확인: 코드]` `metrics.eval_set("train")`만 요청한다. `evaluate.load_eval_sets()["train"]`은 내부에서 test도 만들기 때문에 복사하지 않았다. 비용도 `metrics.eval_costs(train)`만 쓴다.
- `[결정 필요]` 권장안으로 구현: 어휘 fit 모집단은 해당 N에 진행 중인 fit 궤적이다. 실제 모델 대상과 잔차·이슈 빈도 모집단을 일치시켰다 (P5d-D16).
- `[결정 필요]` 진단의 등장 단위는 궤적별 존재다. 후보 중 저장소 최대 점유율 >0.5인 비율, g가 등장한 fit 이슈의 정리된 본문에 g가 한 번이라도 있는 후보의 비율을 쓴다 (P5d-D18). 진단으로 후보를 줄이지 않는다.
- `[결정 필요]` 전체 모드에서 후보가 K개 미만이면 진단·목록을 남기고 **학습 전에 중단**한다. smoke는 경로 점검용 0 패딩만 허용하고 실제 어휘 수·패딩 열을 기록한다 (P5d-D19). t·K 그리드는 바꾸지 않는다.

### 검증

- 미실행. 소스와 기존 함수 계약을 읽어 연결만 검토했다. 실제 후보 수·저장소 ID 형식·진단값·탐색 시간은 확인하지 않았다.
- (t,K) 동률·라벨 방향·fit 경계·전체 모드 후보 부족 중단 테스트를 작성했으며 실행 대기다.

## 5d.2 피처·어휘·누수 테스트 (작성, 실행 전)

### 한 일

- `afp/features.py`에 `extract_thought`, `thought_steps`, `thought_length_features`, `thought_length_columns`를 추가했다. 기존 피처 함수는 변경하지 않았다.
- 모든 백틱 3개 펜스 블록을 제거하고 미완성 블록 이후를 버린다. 코드 블록 뒤 설명도 남기므로 M3의 첫 펜스 앞 정의·600자 제한과 다르다.
- 길이는 추출된 생각의 문자 수다. 평균·최대·마지막·빈 스텝 수와 k=3 창 평균을 집계한다. N≤3이면 창 열은 없다. 스텝 누락·중복은 빈 생각으로 바꾸지 않고 오류 처리한다.
- `afp/thought.py`에 숫자/경로 제거·소문자 단어 1~2-gram, 문서 존재 표현, fold 내부 잔차 연관 점수·양방향 |s| 선택, 스텝/창 존재 횟수·자카드를 작성했다.
- `TrainScope`는 기존 train 명부와 ID·이슈·fold를 대조한다. test·held fold·미등록 ID·위조 fold·이슈 fold 충돌을 거부한다. 통계에 fit ID와 held fold를 묶어 다른 fold의 통계를 재사용하지 못하게 한다.

### 결정과 근거 (기각한 안 포함)

- `[결정 필요]` P5d-D14: null은 빈 문자열, 바깥 공백 제거, 내부 공백 유지, 코드 블록 경계는 공백 하나. 길이는 어휘 정규화 전 문자열 기준이다.
- `[결정 필요]` P5d-D15: 공백 조각에 숫자가 하나라도 있거나 `/`, 역슬래시, `.확장자`가 있으면 조각 전체를 제거하고 bigram을 끊는다. Unicode 문자 단어와 내부 apostrophe 축약어를 허용한다. 문장부호도 경계다. stopword/stemming은 추가하지 않는다.
- `[결정 필요]` P5d-D17: P5d-D12대로 문서는 스텝 생각을 이어 붙인다. 문서 경계 bigram은 선택 후보가 될 수 있지만 모델 피처는 P5d-D4대로 각 스텝 안 출현만 센다. 따라서 경계에서만 나타난 bigram의 모델 피처가 0일 수 있다. 스텝 합집합으로 문서 정의를 바꾸는 안은 적용하지 않았다.
- `[결정 필요]` P5d-D19: |s| 동률은 n-gram 사전순. 분모 0 진단·자카드는 보고용 null로 표시하며 모델 피처에는 null/NaN을 허용하지 않는다.

## 5d.3 학습·비교·S3 인계 경로 (구현, 실행 전)

### 한 일

- 네 묶음 `s2`, `length`, `lexical`, `length_lexical` × 모델 2개 × 모든 N의 OOF 경로를 작성했다. 선택된 `S2+어휘` 탐색 결과는 재사용한다.
- 기존 `04e_m1_window.oof_task`는 전체 fold 공통 행렬이므로 어휘 묶음에는 쓰지 않는다. 각 fold의 어휘로 만든 fit/held 행렬을 따로 학습·채점하는 경로를 작성했다. 학습기·고정 설정·XGB 선택은 기존 코드를 쓴다.
- 같은 실행·장치의 S2를 재학습한다. 5c의 `chg` OOF 파일이 있으면 키·점수를 비교하며, 같은 장치일 때만 점수 비트 일치를 요구한다. 없으면 미검증(null)으로 보고한다.
- 공용 운영점·paired bootstrap을 연결해 단독/결합 정책, K*·K=35 참고 행, 스텝·토큰 절약 및 K*·S2 대비 차이/구간을 출력하도록 작성했다. N 요약에도 토큰과 K* 대비 토큰 차이 [95%]를 포함했다.
- 어휘 fold별 정체·부호·빈도·순위·겹침, 선택 설정, 입력 지문, OOF·열 순서를 인계 메타데이터로 보존한다. 서로 다른 fold의 rank를 같은 단어로 해석하지 않는다.

### 결정과 근거 (기각한 안 포함)

- `[결정 필요]` P5d-D13: S2 = `chg`와 S1 = `w3` 메타데이터를 검사하고 달라지면 중단한다. 5c 점수를 기준으로 바로 읽는 대신 S2를 재학습해 같은 장치 비교를 유지한다.
- XGB 설정은 전체 OOF AUROC, t·K 및 S3는 `m1_xgb`의 이슈 내 쌍 가중 AUROC N∈{8,10,15,20} 평균이다. t·K 동률은 큰 t→작은 K, S3 동률은 적은 피처→묶음 순서다. B1 모델 별도 선택도 기록한다 (기존 규칙).
- `[확인: 코드]` 사용자 후속 지시(2026-11-16)로 XGBoost 학습은 기본 `--device cuda`, `--gpu-jobs 4`다 (P5b-D15). CUDA 불가 시 중단하며 CPU는 `--device cpu`로 명시해야 한다. 텍스트 처리·어휘 선택·운영점·bootstrap은 기존 Polars/NumPy 공용 경로의 CPU 작업이며, 학습 후 예측은 기존 5b 방식의 CPU 트리 채점이다. `--final`은 없고 import/도움말에서 GPU 점검·모델 학습을 하지 않는다.
- bootstrap은 train 이슈 1,000회·`io.SEED`, τ·cap·K* 고정이다. 선택 불확실성은 구간에 들어 있지 않다 (P5b-D13).

### 검증

- **미실행.** 전체 학습·smoke·OOF 재현·부트스트랩·바이트 재현을 하지 않았다. 모델 선택·성능 수치는 없다.
- 소스상 기록 행 수: 준비 72 + 최종 48 − 재사용 12 = 108설계, XGB 8개이면 OOF 864회/5-fold 학습 4,320회 `[가정: 중복 제거 전 설계 산술, PHASE5D_PLAN.md 8절]`. 실제 실행 시간은 추정하지 않았다.

### 산출물

- 실행 후 예정: `results/phase5d/`의 판별·운영점·N 요약·선택·어휘·분포·JSON, `data/processed/phase5d/`의 OOF·어휘 행렬·`handoff.json`.
- smoke는 `data/processed/phase5d_smoke/`만 사용한다. 정식 결과를 덮어쓰지 않는다. 이번에는 어느 경로도 만들지 않았다.
- 전체 실행의 요약은 준비 단계에서 incomplete로 기록하고 완료 시 갱신한다. 중간 실패를 이전 성공 결과로 오인하지 않게 한다.

### 계획과 다른 점

- test 결과를 낼 공통 final 스크립트는 이 단계에 넣지 않았다. 5e 이후 공통 final에서 fold k 어휘·모델·B1 fold k를 함께 사용해야 한다 (P4-D6·D7).
- 원래 예정했던 탐색 판별은 `vocabulary_search_oof.csv`에, 최종 네 묶음 판별/구간은 `discrimination_oof.csv`에 저장한다. 모두 보고한다는 조건을 유지한다.

### 미결

- t·어휘 K·S3·가설 결과 모두 미정. 전체 실행과 전체 재현은 사용자 몫이다. 테스트 통과가 전체 학습 권한을 주지 않는다.
