## 7.0 설계와 사전 등록 (2026-11-09, 학습 실행 전에 커밋)

### M1·M2 결과에서 가져온 설계 근거

| 앞 Phase에서 확인한 것 (출처) | M3 설계 |
| --- | --- |
| 신호가 약하고 과적합이 쉽다. 실효 표본은 궤적 6.2만 개가 아니라 학습 이슈 2,989개다. 가장 작은 XGBoost가 골라졌다 (`docs/phase5.md` 5.3) | 같은 이슈의 궤적은 서로 비슷하다. 그래서 epoch마다 **이슈당 최대 4궤적만** 새로 뽑아 학습한다 (D7 범위 축소). 이슈는 모두 보고 계산량은 약 1/4로 줄인다 |
| 개발 실행이 test를 출력해서 그리드를 넓힐 수 없었다 (P5-D4, P5-D4 배경 → CLAUDE.md 규칙) | 개발 실행(기본)은 **train OOF만** 계산한다. test는 `--final`에서 저장된 fold 모델로 한 번만 채점한다 (재학습 없음) |
| 모델 하나로 모든 N을 학습해도 됐다. 비용이 1/6이었다 (P6-D2) | **모델 하나로 N ∈ {5, 10, 20}** (D7). 한 epoch 안에서 세 N의 예를 섞는다 |
| M2 입력에 사람이 고른 집계(누적 피처)를 넣었더니 오히려 해로웠다 (P6-D5, 6.4 절제) | 피처를 따로 넣지 않는다. **원문만** 넣는다 (제안서 M3 정의). M1 정보는 넣지 않고 M1과 짝지어 비교한다 |
| B1(이슈 본문)을 넣으면 전체 AUROC는 오르고 이슈 내 AUROC는 그대로다 (5.6, 6.4) | 이슈 본문은 입력에 넣지 않는다. B1 정보는 **late fusion stacking**(`m3_bert_b1`)으로 따로 더한다. 입력 길이를 궤적에 다 쓴다 |
| N=10은 스텝으로는 이겼지만 토큰으로는 K\*와 같았다 (5.6) | 모든 운영점 표와 N 요약에 절약 토큰과 K\* 대비 토큰 차이 [95%]를 넣는다 |

### 사전 등록 (이 절은 결과를 본 뒤 고치지 않는다)

**모델** (`code/06_m3.py`)
- `m3_bert`: ModernBERT-base(`answerdotai/ModernBERT-base`, revision `8949b909ec900327062f0ebf497f51aef5e6f0c8` 고정) + 분류 머리(logit 1개, 평균 풀링)다. 모델 하나가 N ∈ {5, 10, 20}을 맡는다
- `m3_bert_b1`: N마다 로지스틱 회귀 [logit M3, logit B1(`b1_n`)] → 실패 (late fusion, C=1.0). fold k 결합기는 fold k를 뺀 train OOF 점수로 학습해 fold k에 적용한다 (`oof.oof_predict`). test fold k는 M3 fold k 점수와 B1 fold k 점수를 결합기 k에 넣는다 (P4-D7 ①). ②는 민감도로만 보고한다

**입력** (7.2, `afp/m3_text.py`): 시점 N 입력 = `[CLS]` + 스텝 1..N 조각 + `[SEP]`. 스텝 조각(토큰 단위 상한)은 `"\n[t]"`(≤4) + 생각 앞 32 + `" $"` + 명령 앞 24 + `" >"` + 관측 앞 26 + `" …"` + 관측 뒤 12다. 합해서 최대 101토큰이다
- 생각 = `action_text`의 첫 코드 펜스 앞부분이다. 명령 = `steps.command`다. 관측에서는 SWE-agent 상태 줄(`parse.TRAILER`)을 뗀다. 관측이 짧으면 전부 넣고, 길면 앞부분과 뒷부분을 넣는다 (파이썬 에러는 보통 끝에 있다)
- N=20에서도 최대 2 + 20 × 101 = 2,022 ≤ 2,048이라 자르지 않는다. 그래서 **입력은 스텝 1..N만 보고 N 이후 스텝은 구조상 들어갈 수 없다** (궤적별 토큰 열의 앞부분)
- 이슈 본문, `exit_status`, `generated_patch`, `eval_logs`는 넣지 않는다

**학습 예** (D7): 시점 N에 진행 중인(n_steps > N) 궤적만 쓴다. epoch마다 N별로 이슈당 최대 4궤적을 새로 뽑는다 (rng = [seed, 1 + epoch]). 같은 궤적이 다른 N의 예로 같이 뽑힐 수 있다. 클래스 가중은 없다

**검증·조기 종료** (CLAUDE.md 누수 방지): fold k 모델은 fold k를 뺀 train으로만 학습한다. 그 안에서 이슈 단위로 1/8을 검증 조각으로 뗀다 (`split.fold_splitter(8, io.SEED)`, M2와 같은 분할기). 검증 예는 N별 이슈당 최대 4궤적으로 고정이다 (rng [seed, 0]). 검증 점수는 N 3개 AUROC의 평균이다. epoch마다 2번 재고 최고 점수의 가중치를 쓴다. fold k와 test는 학습·검증 어디에도 쓰지 않는다

**고정값 (그리드 없음)**: AdamW lr 3e-5, weight decay 0.01(편향·LayerNorm 제외), warmup 6% 후 선형 감소, 최대 2 epoch, 유효 배치 32예, 기울기 노름 1.0, bf16 autocast(가중치 fp32), seed = `lstm.seeds_for(k, 1)[0]`. fold 모델당 학습 약 45분이라 그리드를 돌릴 수 없다. 값은 BERT류 분류 fine-tune의 표준 범위에서 골랐다 [가정: 이 데이터에서 lr을 비교하지 않았다]

**평가 (`--final`)**: 03~05와 같은 `afp/evaluate.py` 함수를 `n_grid=(5, 10, 20)`으로 쓴다. 판별 지표는 fold 평균 점수다 (P4-D2). 운영점은 train OOF에서 3.5%로 고르고, test를 fold 모델별로 채점해 평균한다 (P4-D6). 판정은 test 손실 95% 상한 ≤5%다. K\*=40과 `cap_proposal`(K=35) 행을 같이 둔다

**짝지은 비교** (`paired.csv`, 같은 재표본, 차이 = M3 − 상대)
- 주: `m3_bert` ↔ `m1_xgb`, `m3_bert_b1` ↔ `m1_xgb_b1` (같은 B1 조건에서 가장 강한 M1)
- 보조: 공식 M2(`m2_lstm`, `m2_lstm_b1`)와 누적 집계 없는 M2(`m2x_nocum`, `m2x_nocum_b1`, P6-D11)
- 상대 모델의 운영점은 이 머신의 예측 파일에서 같은 함수로 다시 고른다 (P6-D10)

**해석 규칙**: N 3개 × 정책 2개 중 하나만 통과한 결과는 강조하지 않고 N 전체의 경향으로 쓴다. "M3가 M1보다 낫다"는 주 짝의 AUROC 차이 구간 하한이 0보다 큰 N이 여러 개일 때만 쓴다. M3가 M1보다 나쁘거나 비슷해도 그대로 보고한다

**실행 순서**: 개발 실행(train OOF만) → 출력과 `[주의]`(검증 AUROC < 0.55인 fold)를 보고 → `--final` 한 번. `--final` 결과를 본 뒤에는 설정을 바꾸지 않는다. 개발 실행이 끝났는데 학습이 안 된 fold가 있으면 멈추고 보고한다

**완료 기준** (`--final`, `results/phase7/summary.json`)
- C1: 예측 파일이 진행 중 궤적을 모두 덮는다
- C2: 결합기와 수집이 학습에 쓴 이슈를 채점하지 않는다
- C3: 최종 OOF = 개발 OOF (비트 단위). fold 0 train을 캐시 없이 다시 채점해도 같다
- C4: K\*=40이다
- C5: B1 test 입력이 fold마다 다르다 (P4-D7 ①)
- C6: fold별 파일의 평균이 평균 파일과 같다
- C7: 운영점 표가 모델 2 × N 3 × 정책 2 행이고 fold 범위가 있다
- C8: 상한 기준선 행이 Phase 4와 같다
- C9: ② 민감도가 있다
- C10: 짝지은 비교 값이 모두 있다

### 설계 확인용 측정 (2026-11-09, train만, 사전 등록 전) [확인]

- **입력 길이** (train 궤적 62,225개 = n_steps ≥ 2. 토큰 7,460만 개): 평균 / 최대 길이는 N=5 400 / 507, N=10 818 / 1,012, N=20 1,677 / 2,022다. N=20에서도 2,048 안이다
- **fold당 학습량** (`M3Config()` 기본값): fit 이슈 약 2,390개 → 학습 조각 약 43,560궤적, 검증 조각 약 6,220궤적이다. epoch당 학습 예는 약 23,100개다 (N=5 8,150 / N=10 7,950 / N=20 7,050). 걸음은 약 725, 토큰은 약 2,170만 개다. 검증 예는 약 3,250개다. OOF 채점은 fold당 약 26,500예, 2,130만 토큰이다
- **VRAM** (실제 ModernBERT-base, bf16 autocast, deterministic): 학습 최대 할당 7.5 GiB (가장 긴 N=20 4×2,022 묶음 + AdamW 상태)다. 예측 2.9 GiB다 (총 11.5 GiB). 처음에는 길이가 제각각인 묶음 때문에 캐싱 할당자가 조각나서 OOM 재시도 경고가 한 번 났다 (값은 정상). `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`로 없앴다. 같은 실행에서 예측값이 비트 단위로 같았다
- **처리 시간** [가정: deterministic 모드 벤치마크 처리량으로 추정]: fold당 epoch 약 20분 → 학습 약 45분/fold. 개발 전체(5 fold + OOF 채점)는 **약 4~4.5시간**이다. `--final`(test 채점 + fold 0 재채점 + 부트스트랩)은 약 40분이다. 실측은 7.4에 적는다
  - 2026-11-10 메모: 실측은 fold당 학습 약 31분, 개발 전체 약 3시간, `--final` 약 30분이다 (7.4 검증)
- **결정론**: deterministic 모드에서 같은 설정으로 두 번 학습하면 가중치와 예측이 비트 단위로 같다 (작은 실험) [확인]. 실제 모델 짧은 학습(이슈 150개, 13걸음)에서 저장·읽기 뒤 예측도 같았다. 검증 AUROC는 0.93이다 (작은 검증 조각이라 값 자체는 의미 없음, 학습 경로가 돈다는 확인만)

## 7.1 모델·학습 (`code/afp/m3.py`, 2026-11-09)

### 한 일
- `M3Config`(고정값), `new_model`(revision 고정, fp32 가중치, 평균 풀링, num_labels=1), `model_from_state`
- `sample_examples`(N별 이슈당 최대 k궤적), `inner_split`(검증 조각), `plan_epoch`·`micro_batches`(길이 정렬 덩어리 → 유효 배치 32예 → 토큰 예산 8,192로 나눠 기울기 누적)
- `fit`: 검증 조각 분리 → epoch 계획 → AdamW + warmup·선형 감소 → epoch마다 2번 검증 → 최고 가중치(CPU fp32 사본)를 남긴다
- `predict_examples`: 예 집합만으로 정렬·배치를 정한다 (길이 → 행 → N). 그래서 같은 예 집합이면 결과가 비트 단위로 같다. 토큰 예산은 32,768이다
- `save`·`load`(임시 파일 → 교체), B1 결합(`fit_stacker`·`apply_stacker`, logit 클립 1e-6)

### 결정과 근거
- **HF `Trainer` 대신 직접 짠 학습 루프** (PLAN 7.1 변경). 이유는 세 가지다. (1) epoch마다 이슈 균형 표본을 새로 뽑는다. (2) 길이가 0.4k~2k로 크게 달라 토큰 예산으로 묶어야 12GB에 맞고 패딩 낭비가 적다. (3) deterministic 모드, 검증 조각, 최고 가중치 선택을 M2와 같은 방식으로 직접 통제한다. `Trainer`로도 가능하지만 sampler·collator·callback을 다 바꿔야 해서 코드가 더 길다
- **모델 하나로 N 3개, 이슈당 4궤적** (D7, `[결정 필요]` P7-D2·D3): 이슈당 궤적 수는 중앙값 13, 평균 20.8이다 [확인]. fold 0 학습 조각에서 진행 중인 예는 N 3개 합 약 9.2만이고, 이슈당 4궤적이면 epoch당 약 2.3만(약 1/4)이다. 이슈는 모두 본다. 기각: 전체 궤적 사용(fold당 약 2시간 이상, 5 fold 10시간+). 기각: N별 모델 3개(비용 3배)
- **평균 풀링**: 고정한 체크포인트의 `config.json` 기본값(`classifier_pooling: mean`)을 그대로 쓴다 [확인]. CLS 풀링과 비교하지 않았다
- **bf16 autocast, fp32 가중치**: RTX 5070에서 bf16이 빠르고 손실 스케일링이 필요 없다. 가중치·옵티마이저는 fp32로 둔다
- **검증 1/8, 이슈당 4궤적 고정, epoch당 2번**: 검증 예가 약 3,250개라 AUROC 표준오차가 작다 [가정]. epoch 1 중간부터 재므로 과적합이 빨라도 잡는다
- **deterministic 모드** (P6-D3과 같다): `use_deterministic_algorithms(True)`, `CUBLAS_WORKSPACE_CONFIG=:4096:8`, AdamW `foreach=False`. 처리량이 조금 줄지만 재실행 바이트 동일(CLAUDE.md 재현성)을 위해 받아들인다. 위 시간 추정은 deterministic 모드 기준이다

### 검증 (`code/tests/test_m3.py`, 6개 통과 [확인])
- `sample_examples`: 같은 rng면 같다. (이슈, N)마다 정확히 min(k, 진행 중 궤적 수)개를 뽑는다. 진행 중이 아닌 궤적은 뽑지 않는다
- `inner_split`: 검증 조각은 fit 행 안의 이슈 단위 부분집합이다
- `plan_epoch`·`micro_batches`: 모든 예를 정확히 한 번 덮고, 묶음마다 (예 수 × 최대 길이) ≤ 토큰 예산이다
- 작은 무작위 ModernBERT(CPU): 같은 seed로 두 번 학습하면 가중치·예측이 같다. 저장·읽기 뒤 예측이 같다. 예 순서를 바꿔 넣어도 예측이 같다
- **fit 밖 행의 라벨·토큰을 바꿔도 학습 결과가 같다** (조기 종료·검증이 fit 행 안에서만 이뤄진다)
- 결합기: fold k 라벨을 뒤집어도 fold k의 OOF 결합 점수가 같다

## 7.2 텍스트 입력 (`code/afp/m3_text.py`, 2026-11-09)

### 한 일
- `steps.parquet`에서 스텝 1..min(n_steps − 1, 20)의 `action_text`·`command`·`obs_text`만 읽는다 (`io.scan_steps`가 누수 컬럼을 거부한다)
- 문자열을 먼저 자른다 (생각 600, 명령 400, 관측 앞 600 / 뒤 300자, 메모리용). 그다음 토큰 단위로 자른다
- 궤적마다 조각을 이어 붙인 토큰 열 하나와 누적 길이 `ends`를 저장한다 (`TextData`). 시점 N 입력은 이 열의 앞부분이다
- 캐시: `data/processed/m3/text_{train,test}/` (토큰 배열 + 지문). 지문은 궤적·스텝 원문·토크나이저 revision·예산으로 정한다
- `budget()`을 결과 JSON에 기록한다

### 결정과 근거

- **상태 줄 제거**: SWE-agent 관측 끝의 `(Open file: …) (Current directory: …) bash-$`는 모든 스텝에 반복된다. 열린 파일 정보는 명령에 이미 있다

## 7.3 범위 축소와 실행 스크립트 (`code/06_m3.py`, 2026-11-09)

### 한 일
- 개발(기본): 텍스트 캐시 → fold 모델 5개 학습(meta가 같으면 건너뛰어 이어서 할 수 있다) → `oof.oof_predict`로 train OOF 수집 (fit 콜백은 학습하지 않는다. 저장된 fold k 모델을 읽고 학습 이슈 해시를 대조한다) → B1 결합 → train 운영점(K\* 대비 스텝·토큰) → M1·M2와 train OOF 비교
- `--final`: 개발 요약의 데이터 지문·장치를 대조한다 → test 텍스트 → fold 모델별 test 채점 → fold 0 train 재채점(C3) → 예측 파일(`m3_bert`, `m3_bert_b1`, fold별 파일) → 판별·운영점·부트스트랩 → ② 민감도 → 짝지은 비교 → Phase 4~6과 비교 표(N 5·10·20) → N 요약 → 완료 기준 C1~C10
- `--smoke`: 무작위 초기화한 작은 ModernBERT로 train 이슈 480개를 가짜 train/test로 나눠 위 경로를 모두 돈다. `data/processed/m3_smoke/`에만 쓴다 (실제 test·예측 파일은 건드리지 않는다)
- 채점 캐시: `scores/{train|test}_fold{k}.parquet`. 키는 (모델 meta, 데이터 지문, 행, N)이다

### 결정과 근거
- **N=5, 10, 20만** (D7 확정): 제안서 "남은 일"의 축소안이다. 작은 N(3)은 M1도 신호가 약하고, 8·15는 이웃 N으로 경향을 볼 수 있다
- **B1 결합은 late fusion** (`[결정 필요]` P7-D1): M3 점수와 B1 점수의 N별 로지스틱 회귀다. fold k 결합기는 fold k를 뺀 OOF로만 학습한다. 한계(stacking): M3 OOF 점수를 낸 fold j 모델은 fold k를 포함해 학습했다 (P4-D7과 같은 수준, 기록만 한다). 기각: 이슈 본문을 입력에 넣는 안 (P7-D5)
- **결과 파일에 실행 시간을 쓰지 않는다**: 처음에는 `train_log.csv`·`summary*.json`에 초·분을 썼다. 그래서 `--force` 재학습 결과가 바이트 단위로 달랐다. 시간은 `models/fold*.json`과 표준 출력에만 남긴다
- **개발 경로는 test를 보지 않는다**: 개발 모드는 test 텍스트를 만들지 않는다. B1 test 점수와 다른 모델의 test 행도 읽지 않는다. M1·M2 비교는 `results/phase5·6`의 train 행뿐이다

- **M3는 비용 절약에서 M1·M2보다 분명히 못하다.** N=20 결합 정책이 K\*보다 스텝 +3.7%p, 토큰 +3.8%p를 더 아끼지만, M1 XGB(+7.5 / +9.1)의 절반 정도다. 짝지은 차이 구간이 모두 0 아래다
- N=20에서 M3는 스텝으로는 제안서 K=35(+3.6%p)와 비슷하고, 토큰으로는 K=35(+6.3%p)보다 적다. 손실은 K=35보다 낮다 (2.5% vs 3.1%)
- train OOF에서 고른 τ가 0.98~0.999로 매우 높다. OOF 점수가 실패 쪽으로 몰려 있고 상위 꼬리의 순서가 약하다는 뜻이다 [가정]. N=5 결합 정책은 0.08%만 끊어 사실상 K\*와 같다
- 단독 정책은 N=5·10에서 K\*보다 덜 아낀다 (M1·M2와 같은 경향). N=20 단독은 스텝 +2.5%p로 이기고 토큰은 +0.7%p [−1.5, +2.8]로 K\*와 같다
- 손실 구간 폭(결합 중앙값): `m3_bert` 0.80%p로 M1 XGB(0.85%p)와 같은 수준이다. 덜 끊어서 좁다 (`loss_ci_width_summary.csv`)

### 결론 (K\* 대비, N 전체 경향)
1. **판별은 M1·M2와 같은 수준이다.** 평균 점수 AUROC는 N=5에서 가장 높지만 하나의 N뿐이고, 5개 모델 평균 효과(+0.03) 덕분이다. 이슈 내 AUROC는 N≥10에서 낮다
2. **비용 절약은 M1·M2보다 못하다.** N=20 결합 정책이 K\*보다 스텝 +3.7%p · 토큰 +3.8%p를 더 아끼지만, M1 XGB보다 스텝 −3.6%p · 토큰 −5.1%p 적다 (구간이 0 아래)
3. **B1 결합은 test에서 도움이 되지 않았다** (M1·M2와 다르다)
4. 비용: fold 모델 5개 학습 약 2.6시간(GPU) + 채점. M1(CPU 약 4.5분)과 M2(GPU 약 11분)보다 수십 배 비싸다. **이 설정의 M3는 M1을 대신할 이유가 없다**
5. 한계: 하이퍼파라미터 그리드가 없다 (P7-D3). 0.5 epoch 뒤 과적합하고 fold 사이 차이가 크다. 더 낮은 lr, 더 많은 궤적, 여러 seed 평균은 시도하지 않았다. test를 본 뒤라 이번 결과로 설정을 바꾸지 않는다
