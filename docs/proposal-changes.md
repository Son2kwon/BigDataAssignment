# proposal.md 수정 내역과 이유

`docs/proposal.md`를 2026-10-18~19에 검토하고 수정한 내용을 정리한 문서다. 팀원(또는 팀원이 쓰는 AI)이 "왜 이렇게 바뀌었는지" 확인할 수 있도록 수정 전 → 수정 후 → 이유 순서로 적었다.

- 과제 요구사항: Problem & Motivation / Data / Method & Evaluation / Expected Outcome. 제출 마감 10월 22일, 최종 발표 13~14주차. 팀은 2인까지이고 두 명이 균등하게 기여해야 한다.
- 파일 위치: `proposal.md`를 루트에서 `docs/proposal.md`로 옮겼다.

## 수정 내역

### 1. 팀 정보 칸 추가 (제목 아래)
- **수정 후:** 팀원 / 학번 / 담당 표 (빈칸)
- **이유:** 과제 규정상 2인 팀은 사전 합의가 필요하고 두 명이 균등하게 기여해야 한다. 제안서에 팀 구성과 분담이 없었다. **→ 팀원이 직접 채워야 함.**

### 2. 일정: 날짜 → 주차 (§7)
- **수정 전:** 10월 말 / 11월 초~중순 / 11월 말 / 12월
- **수정 후:** 8주차 ~ 12주차 주별 작업 + "최종 발표는 13~14주차, M3·외부 테스트가 늦어지면 B0·B1·M1·M2 결과로 발표"
- **이유:** 최종 발표가 13~14주차(11월 말~12월 초)인데 기존 일정은 12월에 결과 정리를 두어 발표와 겹쳤다. 12주차 안에 결과가 나오도록 당겼다.

### 3. 모델 간 분할 설명 (§4 분할)
- **수정 전:** `idea 단계의 "2종 학습 → 1종 테스트"는 70B가 전체의 93%라 학습 데이터가 부족해서 이렇게 바꿨다.`
- **수정 후:** 처음 계획(모델 2종 학습 → 1종 테스트)과 바꾼 이유 두 가지를 풀어 씀.
  1. 70B를 테스트로 빼면 학습 데이터가 5,244개만 남는다.
  2. 70B로 학습하고 8B·405B로 테스트하면 같은 이슈가 학습과 테스트에 모두 들어간다. 8B·405B가 시도한 578개 이슈는 70B도 모두 시도했다(70B 궤적 12,332개).
- **이유:** 교수님은 idea 단계 문서를 보지 않으므로 내부 맥락 없이 읽혀야 한다.

### 4. "8B·405B가 푼 이슈" → "시도한 이슈" (§4 분할)
- **이유:** "푼"은 "성공한"으로 읽혀 성공한 이슈만 테스트로 고른 편향된 설계처럼 보인다. 실제로는 시도한 이슈다. 8B·405B 궤적 5,244개가 모두 이 578개 이슈 안에 있다.

### 5. "정답 파일 열람"은 사후 분석용으로 한정 (§3 누수 점검, §5)
- **수정 전:** 실패 신호 후보에 "이슈와 관련 없는 파일 탐색", 근거로 "정답 파일을 연 비율 성공 83% / 실패 40%"
- **수정 후:**
  - 후보를 "이슈 본문에 언급된 파일을 열지 않는 탐색"으로 바꿈
  - "정답 파일은 정답 패치를 알아야 정해지므로 운영 중에 계산할 수 없다. 피처로 쓰지 않고 사후 분석에만 쓴다" 추가
  - 누수 점검 목록에 "정답 패치를 알아야 계산되는 값은 피처로 쓰지 않는다" 추가
- **이유:** 정답 파일은 gold patch(사람이 실제로 고친 코드)로 정해진다. 운영 중인 에이전트는 이를 모르므로, 피처로 쓰면 라벨 누수가 되어 성능이 부풀려진다.

### 6. 이슈 내 AUROC 계산 대상 (§4 지표)
- **수정 전:** "성공·실패가 섞인 이슈 807개 안에서만 계산"
- **수정 후:** "테스트 이슈 중 성공·실패가 섞인 이슈 안에서만 계산 (전체 데이터 기준 807개)" + "N이 커질수록 계산 가능한 이슈가 줄어들므로 N별로 이슈 수를 함께 보고"
- **이유:**
  - 807개는 전체 데이터 기준이고, 평가는 테스트 이슈에서만 한다.
  - 시점 N에서는 N스텝 넘게 진행 중인 궤적만 남는다. 성공 궤적은 짧아서(중앙값 12스텝) 먼저 빠지므로 N이 클수록 성공·실패가 섞인 이슈가 줄어든다.

### 7. PR-AUC 기준 클래스 설명 (§4 지표)
- **수정 후:** "PR-AUC는 성공 클래스 기준. 성공은 소수(16.7%)이고 잘못 끊었을 때 손해가 가장 큰 쪽이라, 성공 궤적을 얼마나 놓치지 않는지 본다. 무작위 예측의 PR-AUC는 해당 시점의 성공률(N=10에서 0.138)과 같다"
- **이유:** 모델은 "실패 확률"을 내는데 PR-AUC는 "성공 기준"이라 이유 없이는 헷갈린다. 무작위 기준값을 적어야 PR-AUC 숫자를 해석할 수 있다.

### 8. 고정 상한 표에 K=35 추가 (§4)

### 10. 학습 fold: GroupKFold → StratifiedGroupKFold (§4 분할, 구현 단계 2026-10-29)
- **제안서:** "하이퍼파라미터는 학습 이슈 안에서 5-fold GroupKFold로 고른다"
- **구현:** 그룹은 그대로 `instance_id`이고, `target`으로 층화한 `StratifiedGroupKFold(5, shuffle=True, random_state=42)`를 쓴다. 테스트 궤적은 fold = -1 (어떤 fold에도 속하지 않음)
- **이유:** 이슈 성공률 편차가 커서(학습 이슈의 77.3%가 성공 0) GroupKFold로는 fold 성공률이 14.4%~17.5%로 벌어진다. fold마다 PR-AUC 무작위 기준값과 운영점 τ 선택 조건이 달라진다. 층화하면 16.2%~16.3%. 같은 이슈가 두 fold에 들어가지 않는 성질은 그대로다
- **근거:** `results/phase2/fold_balance.csv`, PLAN.md Phase 2 결과

### 11. 고정 상한 비교 기준: K=35 → 학습 이슈에서 고른 K\*=34 (§4·§5, 구현 단계 2026-10-31)
- **제안서:** "예측 모델은 성공 손실 5% 이하에서 K=35의 24.6%보다 많이 절약해야 한다"
- **구현:** 모델의 τ·K를 학습 이슈 OOF에서만 고르는 원칙(PLAN 3.5)을 고정 상한에도 적용해, train 62,460궤적에서 손실 ≤5%인 가장 작은 K를 고른다 → **K\*=34** (train 손실 4.71%, 절약 25.06%). 모델 운영점은 같은 평가 집합·같은 부트스트랩 표본의 K\*=34와 비교한다. 제안서 K=35는 같은 표에 참고 행으로 둔다 (`results/phase4/operating_points.csv`의 `cap_proposal`)
- **이유:** K=35는 테스트 궤적을 포함한 전체 데이터에서 고른 값이라 테스트 정보가 기준선 선택에 들어간다. 차이는 작다 (test_same 손실 4.95% vs 4.47%, 절약 22.64% vs 21.81%)
- **확정 (회의 2026-11-05, PLAN.md 11절 P4-D1).** 70B 무작위 분할(14번)에서는 35, 손실 기준 변경(15번) 뒤에는 **40**

### 12. B1 이슈 본문에서 "고칠 파일 목록" 꼬리 제거 (§3 누수 점검, 2026-10-31)
- **발견:** 이슈 13개(모두 학습 이슈)는 본문이 2가지이고, 한쪽 끝에 `Here is the list of files that is recommended to be edited in order to fix the issue.\nFILES TO MODIFY:\n- <경로>`가 붙어 있다 (궤적 26개, 모두 실패)
- **구현:** B1 입력에서 이 꼬리를 지운다. 지운 뒤 3,591개 이슈 모두 본문이 1개다 (`baselines.strip_hint`, `test_real_issue_text_unique_after_strip`)
- **이유:** 고칠 파일 목록은 정답 패치에서 나온 정보다. 제안서 §3 "정답 패치를 알아야 계산되는 값은 피처로 쓰지 않는다"에 해당한다

### 13. OOF 모델의 테스트 점수: 5개 fold 모델 평균 (§4, 2026-10-31)
- **계획(PLAN.md 4.3):** 테스트 점수는 학습 이슈 전체로 다시 학습한 B1으로 낸다
- **구현:** 학습 OOF 점수를 만든 5개 fold 모델 점수의 평균 (`oof.oof_predict`, M1~M3도 같은 함수)
- **이유:** 운영점 τ를 OOF 점수 위에서 고르고 테스트에 그대로 쓰므로, 학습 데이터 양이 OOF 모델과 같은 모델의 점수가 척도가 맞는다. M1은 학습 때 B1 OOF 점수를, 테스트 때 B1 테스트 점수를 피처로 본다. 실측 차이는 작다 (테스트 AUROC 차이 ≤0.004, `results/phase4/b1_scale.csv`)
- 2026-11-05 17번: 위 "M1은 테스트 때 B1 테스트 점수를 피처로 본다"는 fold 평균 점수가 아니라 **M1 fold k 모델에 B1 fold k 모델의 테스트 점수**를 넣는 것으로 정했다. 평균 점수는 M1 입력으로 쓰지 않는다
- 2026-11-05 16번으로 운영점 평가 방식 변경: 평균 점수는 판별 지표에만 쓴다. 위 "척도가 맞는다"는 이유는 운영점에 대해서는 맞지 않았다 (평균 점수는 분포가 가운데로 모여 OOF 점수보다 높은 τ를 덜 넘는다)

### 14. 테스트 분할: "8B·405B 시도 이슈" → 70B 이슈 층화 무작위 추출, 8B·405B 제외 (§4 분할, 2026-11-05)
- **제안서:** "8B·405B가 시도한 이슈 578개(16.1%)를 테스트 이슈로 고정한다 … 8B·405B 궤적(5,244개)은 다른 모델 일반화 테스트로 쓴다"
- **구현:** 평가는 70B 궤적(74,792개)만 쓴다. 70B 이슈 3,591개를 `StratifiedGroupKFold(6, shuffle=True, random_state=42)`(그룹 = `instance_id`, 층화 = `target`)로 6조각 내고 0번 조각을 테스트로 쓴다 → **테스트 이슈 602개(16.8%) / 궤적 12,481개, 학습 이슈 2,989개 / 궤적 62,311개**. 학습 이슈는 전처럼 5-fold StratifiedGroupKFold. 8B·405B 궤적은 `splits.parquet`에 넣지 않고 어떤 평가 집합에도 쓰지 않는다 (제안서 수치 재현 검사 K=35 4.9%/24.6%, 오라클 0.945에만 전체 80,036궤적을 쓴다)
- **이유 (회의 2026-11-05 §4.3):** 예전 테스트 이슈는 "8B·405B가 시도한 이슈"라 무작위 표본이 아니었다 (궤적 성공률 18.7% vs 학습 16.3%, 저장소 비율 총변동거리 0.63). train OOF에서 고른 B1 τ가 진행 중 궤적의 18.8%를 끊다가 test_same에서는 7.8%만 끊는 문제(P4-1)의 원인 후보였다. 테스트를 학습 fold와 같은 방식으로 뽑으면 "fold 사이 이전"과 "train → test 이전"을 같은 조건으로 비교할 수 있다
- **결과:** 학습/테스트 성공률 16.66% / 16.70%. B1 τ의 test/train 정지율 비가 0.41 → 0.82 (N=10 단독)로 좋아졌고, 학습 없는 B0 규칙은 1.04~1.08로 fold 사이 범위 안이다. 남은 B1 차이는 테스트 점수가 5개 fold 모델의 평균이라 꼬리가 줄어드는 탓이다 (fold 모델 하나로 채점하면 fold 사이 범위 안). 자세한 수치는 PLAN.md Phase 4 "운영점 이전성"
- **영향:** 제안서 결과 5번 "70B 같은 모델 테스트 vs 8B·405B 다른 모델 테스트"와 Phase 8.1(test_cross)은 범위에서 빠진다. 고정 상한 기준선 K\*는 새 train에서 다시 골라 **35**가 됐다 (K=34의 train 손실이 5.04%). 제안서 K=35와 같은 값이다
- 이 항목의 수치(K\*=35, 정지율 비 0.82)는 선택 기준 5% 당시 값이다. 15번 이후 주 결과는 3.5% 기준이다 (K\*=40, N=10 B1 단독 정지율 비 0.74)

### 15. 성공 손실 기준: "손실 ≤5%" → 선택 train 손실 ≤3.5% / 판정 test 손실 95% 구간 상한 ≤5% (§4·§5, 2026-11-05)
- **제안서:** "예측 모델은 성공 손실 5% 이하에서 K=35의 24.6%보다 많이 절약해야 의미가 있다" (운영점 선택과 충족 판정이 같은 5% 점추정)
- **구현:** 두 기준으로 나눈다 (`code/afp/metrics.py`의 `SELECT_MAX_LOSS`, `JUDGE_MAX_LOSS` 한 곳)
  - **선택:** train(OOF)에서 τ·K와 고정 상한 K\*를 고를 때 "train 손실 ≤3.5%". 기준선과 모델에 같은 규칙
  - **판정:** 테스트에서 "충족" = 성공 손실의 이슈 단위 부트스트랩 95% 구간 상한 ≤5%. 점추정이 5% 이하여도 상한이 5%를 넘으면 불충족
  - 3.5%는 고정값이고 테스트 결과를 보고 바꾸지 않는다. 5%로 골랐을 때의 결과는 민감도 표(`operating_points_sensitivity.csv`, `max_loss=0.05`)에 남긴다. 제안서 K=35는 참고 행(`cap_proposal`)으로 둔다
- **이유 (회의 2026-11-05 §4.1):** train에서 한도 5%에 거의 맞춰 고르면 테스트 손실이 5%를 넘기 쉽고, 점추정만 보면 구간이 5%를 넘어도 "충족"이 된다. 테스트 손실의 95% 구간 폭이 예전 분할에서 약 ±1.4%p였으므로, 상한 5%를 지키려면 점추정이 약 3.5~3.6%여야 한다
- **결과 (70B 무작위 분할):** K\* = **40** (train 3.49% / 절약 스텝 20.21%, test 2.02% [1.30, 2.90] / 19.83% / 토큰 34.43%). 판정을 통과하면서 K\*보다 절약 스텝이 유의하게 많은 정책은 B0 결합 정책뿐이다 (에러 수 N=5~20, 편집 실패 수 N=8~20, +0.2~+2.3%p). B1은 없다. 새 분할의 테스트 손실 구간 반폭(참고): K\* ±0.8%p, 모델 운영점 중앙값 ±1.35%p (0.70~3.54). 자세한 표는 PLAN.md "손실 기준 변경" 절
- **영향:** 제안서의 비교 기준 "K=35, 24.6%"는 "train에서 고른 K\*=40"으로 바뀐다. K=35는 test에서 판정 기준은 통과하지만(상한 4.13%) train 손실 4.60%라 선택 기준으로는 고를 수 없다

### 16. OOF 모델의 운영점 평가: 평균 점수 → 테스트를 fold 모델별로 채점 (§4·§5, 2026-11-05)
- **구현됨 (2026-11-05, PLAN.md "Phase 5 선행: P4-D6·P4-D7 구현" 절):** `evaluate.attach_fold_scores` + `test_point`·`bootstrap_stat`·`model_curves`. fold별 test 점수는 `preds/<model_id>.test_folds.parquet`
- **제안서:** 운영점의 테스트 점수 계산 방식을 따로 정하지 않았다 ("학습 이슈에서 τ를 고르고 테스트에 적용"). 구현은 13번대로 5개 fold 모델 평균 점수에 τ를 적용했다
- **구현:** OOF로 학습하는 모델(B1, M1~M3)의 운영점 평가(비용 곡선, 운영점 적용, 판정)에 적용한다. B0 규칙은 학습이 없어 해당 없다
  - 테스트 궤적을 5개 fold 모델이 각각 채점한다 (`oof.OOFResult.test_fold_scores`, 새로 학습하지 않음)
  - train OOF에서 고른 τ·K(선택 기준 3.5% 그대로)를 fold 모델별 점수에 각각 적용하고, 정지율·손실·절약 스텝·절약 토큰은 5개 결과의 평균을 보고하며 범위(min~max)를 함께 적는다
  - 구간은 이슈 단위 부트스트랩의 각 반복에서 5개 결과를 평균한 값으로 만든다. 판정은 15번 그대로, 그 평균 손실의 95% 구간 상한 ≤5%
  - 판별 지표(AUROC, PR-AUC, 이슈 내 AUROC)는 13번대로 5개 fold 모델 평균 점수로 계산한다. 순위 기반이라 점수 척도의 영향을 받지 않는다
- **이유 (PLAN.md 11절 P4-D6):** τ는 OOF 점수, 즉 fold 모델 하나가 낸 점수의 척도에서 고른다. 테스트 점수를 fold 평균으로 내면 분포가 가운데로 모여 높은 τ를 넘는 궤적이 줄어든다 (척도 불일치). 새로 학습할 필요도 없다
  - 기각 (a) 정지율로 운영점 고정: 손실을 직접 통제하지 못한다
  - 기각 (b) τ 선택 점수를 fold 평균 방식에 맞춤: τ를 고를 때 쓸 점수를 따로 만들어야 하고, train에서 fold 평균에 해당하는 점수를 정의하기 어렵다
- **근거 (`results/phase4/tau_transfer_summary.csv`, 선택 기준 3.5%):** N=10 `b1_n` 단독 정지율 비(적용한 곳 / 고른 곳)는 fold 사이 0.80~1.32, 같은 운영점을 fold 모델 하나로 채점한 test에 적용하면 0.79~1.18로 fold 범위 안이고, 평균 점수로 채점한 test는 0.71~0.83이다 (주 운영점 → test 0.74). `b1_static` 단독도 fold 0.80~1.17, fold 모델 하나 0.89~1.06, 평균 0.75~0.83. 같은 운영점을 적용한 B1 120쌍(모델 2 × 정책 2 × N 6 × fold 5) 중 89쌍에서 평균 점수 쪽 정지율이 fold 모델 하나 쪽보다 낮거나 같다 (`tau_transfer.csv`). 이 비교의 운영점은 fold k를 뺀 학습 이슈에서 고른 것이라, 학습 이슈 전체에서 고른 주 운영점을 5개 fold 모델에 적용하는 이번 방식과 같지는 않다
- **영향 (결정 당시):** 당시 `results/phase4/operating_points.csv`의 B1 행은 평균 점수 기준이었다 (N=10 B1 4개 정책 모두 판정 불충족). 다음 PR에서 B1 운영점을 다시 계산하고 판정을 확인한 뒤 Phase 5(M1)에 같은 규칙을 쓴다. B0 행·K\*·판별 표는 바뀌지 않는다
- **결과 (구현 후):** B0 행·K\*=40·판별 표는 바이트 단위로 같다. B1은 τ가 더 많이 끊어 손실과 절약이 함께 늘었다 (N=10 `b1_n` 단독 정지율 11.1% → 13.3%, 손실 2.50% → 3.89%, 절약 10.51% → 11.43%). 단독 정책 test/train 정지율 비가 0.72~0.90 → 0.88~0.97 (모든 N)로 좋아졌다. N=10 B1 4개 정책은 여전히 판정 불충족(손실 상한 5.6~7.4%). N=3~20에서 판정을 통과하면서 K\*보다 유의하게 더 아끼는 B1 정책이 처음 하나 생겼다: `b1_static` 결합 N=20 (K\* 대비 +1.44%p [+0.14, +2.93], 손실 상한 4.28%). B1 판정 통과는 24개 중 8 → 9개

### 17. M1의 테스트 B1 입력: fold 평균 점수 → M1 fold k에 B1 fold k 점수 (§3·§4, 2026-11-05)
- **입력 경로 구현됨 (2026-11-05):** `preds.load_feature(model_id, "train")` → OOF, `preds.load_feature(model_id, "test", fold=k)` → fold k 점수(①), fold 없이 test를 요청하면 에러(③), `preds.load_feature_other_folds(model_id, k)` → j≠k 4개(②). M1 학습·② 민감도 결과는 Phase 5
- **제안서:** M1은 B1 점수를 포함/제외한 두 버전으로 학습한다 ("M1(±B1)"). 테스트에서 어떤 B1 점수를 넣을지는 정하지 않았다. 13번 구현대로라면 테스트 입력은 B1 5개 fold 모델의 평균 점수였다 (`preds/b1_n.parquet`의 test 행)
- **구현 (P4-D7, 구현은 Phase 5 선행 작업):** 테스트에서 M1 fold k 모델(fold k를 뺀 train으로 학습한 M1)에 넣는 B1 점수를 정한다
  - **① 주 방식 (고정):** B1 fold k 모델이 채점한 테스트 점수
  - **② 민감도 (보고만):** M1 fold k 모델을 B1 fold j(j≠k) 모델 4개의 테스트 점수로 각각 채점하고 평균한다. 결과를 보고 주 방식을 바꾸지 않는다. 테스트 결과로 방식을 고르면 테스트 정보가 선택에 들어가기 때문이다. ①과 차이가 크면 한계로 기록한다
  - **③ 금지:** B1 5개 fold 모델의 평균 테스트 점수를 M1 입력으로 쓰지 않는다
  - 16번(P4-D6)과의 관계: 운영점 평가는 M1 fold k 모델 5개(각각 ① 입력)로 테스트를 채점해 각각 τ·K를 적용하고 결과를 평균한다. 판별 지표는 같은 5개 M1 점수의 평균으로 계산한다 (13번 P4-D2)
  - M2·M3가 B1 점수를 입력으로 쓰게 되면 같은 규칙을 따른다
- **이유:**
  1. M1의 학습 피처는 B1 OOF 점수, 즉 B1 모델 하나가 낸 점수다. 평균 점수는 분포가 가운데로 모여서 학습 때와 성질이 다른 피처가 된다
  2. **정확한 범위:** ①이 맞추는 것은 척도, 즉 "모델 하나가 낸 점수"라는 성질이다. M1 fold k의 학습 피처는 B1 fold j(j≠k) 모델들이 만들었고, B1 fold k 모델은 그 생성에 쓰이지 않았다. 따라서 "k끼리 짝"에 특별한 통계적 이유는 없고, ①은 단순함 때문에 고른 것이다. 학습 피처의 출처와 정확히 같은 방식은 ②다
  3. 누수 없음: 테스트 이슈는 B1·M1 어떤 fold 모델의 학습에도 쓰이지 않았다
- **근거 (`results/phase4/tau_transfer_summary.csv`, 선택 기준 3.5%, N=10 단독 정지율 비):** 평균 점수로 채점한 test는 `b1_n` 0.71~0.83, `b1_static` 0.75~0.83으로, 하한이 fold 사이 범위(`b1_n` 0.80~1.32, `b1_static` 0.80~1.17) 아래로 벗어나고 fold 범위의 아래쪽 끝에 몰린다. 같은 운영점을 fold 모델 하나로 채점한 test는 `b1_n` 0.79~1.18, `b1_static` 0.89~1.06이다. 이 수치는 B1 자체의 운영점에서 잰 것이고, M1 피처로서의 영향은 Phase 5 선행 작업의 분포 확인 표(B1 OOF·fold별 테스트·평균 테스트 점수의 표준편차와 분위수)로 따로 확인한다
- **한계 (stacking):** M1 fold k의 학습 피처를 만든 B1 fold j 모델은 fold k를 포함해 학습했다. 그래서 M1의 OOF 점수에 fold k 정보가 아주 간접적으로 섞인다. 일반적인 stacking에서 허용하는 수준이라 그대로 두고 한계로만 기록한다 (중첩 교차검증은 하지 않음)
- **영향:** `preds/b1_n.parquet`(`preds.load_feature("b1_n")`)의 test 행은 M1 입력으로 쓰지 않는다. B1 테스트 점수를 fold별로 저장하는 작업과 분포 확인 표가 Phase 5 선행 작업에 들어간다. Phase 5 완료 기준에 ② 민감도 결과가 들어간다
- **결과 (분포 표 `results/phase4/b1_score_dist.csv`):** N=10 `b1_n` 표준편차 OOF 0.0396, test fold별 0.0334~0.0401 (평균 0.0366), test 평균 점수 0.0343. 평균 점수는 fold 점수보다 표준편차가 5~8% 작고(모든 N) OOF보다 10~15% 작다. 압축은 주로 아래쪽 꼬리에서 나타난다 (q05 fold 0.795~0.816 → 평균 0.811, q95는 0.924~0.928 → 0.927)

### 18. "정답 파일 열람 비율 성공 83% / 실패 40%": 근사로 계산, 재현되지 않음 (§5, 2026-11-06)
- **제안서:** "데이터 카드에서 정답 파일을 한 번이라도 연 비율은 성공 83%, 실패 40%였다 … 사후 분석에만 쓴다" (5번 수정 후 문구)
- **구현:** 이 데이터에는 정답 패치가 없다 [확인: 원본 컬럼과 `eval_logs` 내용]. 정답 파일을 "같은 이슈의 다른 성공 궤적 `generated_patch`가 고친 기존 비테스트 파일"로 근사해 계산했다 (`afp/leakage.py`, `code/04b_solution_files.py`). 피처로 쓰지 않는다는 점은 그대로
- **결과:** 성공 99.7% / 실패 84.3% (근사를 만들 수 있는 궤적 35,331개). 데이터 카드 값은 재현되지 않았다. 근사는 다른 성공 궤적이 있는 이슈에서만 정의되어 성공이 없는 이슈의 궤적 44,705개가 빠지고, 성공 궤적은 근사 파일(다른 성공 패치와 같은 파일)을 거의 항상 연다. 방향(성공이 더 자주, 더 일찍 연다)은 같다: 앞 N스텝 기준 성공 − 실패 차이 N=5~20에서 15~17%p. 자세한 표는 [docs/phase5.md](phase5.md) 5.5
- **영향:** 발표에서 이 수치를 쓸 때는 데이터 카드 값으로 인용하고, 우리 근사 결과는 한계와 함께 따로 둔다. 정답 패치 출처를 추가할지는 PLAN.md 11절 P5-D6 `[결정 필요]`

### 19. M2: "행동 토큰 시퀀스 + 스텝 피처" → 누적 집계 추가, 모델 하나로 모든 N (§3 모델, 2026-11-07)
- **제안서:** M2 = LSTM, 입력 "스텝별 행동 토큰 시퀀스 (`open`, `edit`, `search`, `python` 등) + 스텝 피처", 기대 정보 "행동 순서 정보" (§3 표)
- **수정 후:** 스텝 t 입력 = 명령 임베딩 + 스텝 피처 11개 + **시점 t의 M1 누적 집계 41개** (`afp/sequences.py`). 모델 하나가 위치 t마다 시점 t 진행 중 궤적의 실패 확률을 낸다 (N별로 따로 학습하지 않음). B1 포함/제외 두 종 (PLAN 11절 P6-D1·D2·D5)
- **이유:** M1(Phase 5)에서 신호의 중심이 횟수 피처였고(SHAP 1위 `n_edit_ok`), 가장 작은 XGBoost가 골라질 만큼 신호가 약하고 데이터가 적었다 (학습 이슈 2,989개). 누적 집계를 넣으면 M2는 매 시점 M1과 같은 정보를 가지므로, M1과의 차이를 "순서 정보 + 모든 N 공동 학습"의 효과로 읽을 수 있다
- **제안서 형태와의 비교:** 누적 집계를 뺀 원래 형태(`m2x_nocum`)와 순환을 뺀 형태(`m2x_norec`)를 절제 실험으로 같이 학습한다. train OOF만 보고 test는 채점하지 않는다 (docs/phase6.md 6.0 사전 등록)
- **영향:** M2 결과는 M1과 짝지은 비교(`results/phase6/m2_vs_m1.csv`)로 보고한다. 제안서 예상 학습 시간 "LSTM 실험당 10~30분"은 GPU 실측으로 갱신한다 (docs/phase6.md 6.4)
- **결과 (2026-11-07, docs/phase6.md 6.4):** 누적 집계는 train OOF에서 오히려 해로웠다 (빼면 AUROC +0.012). 주 결과는 사전 등록대로 누적 집계 포함판이다. 원래 제안서 형태의 test 평가는 PLAN 11절 P6-D9 (확정: 보조 실험으로 함, docs/phase6.md 6.5). **보조 실험 결과 (6.5):** 원래 제안서 형태(누적 집계 없음)가 test에서도 누적 포함판보다 낫고 (N≥10 AUROC +0.013~+0.031), M1 XGB와 같은 수준이다. 주 결과는 사전 등록대로 누적 포함판으로 둔다. 학습 시간: 그리드·절제 전체(fold 모델 70개 × seed 3)가 GPU 약 10.6분

### 20. M3: "궤적 원문 Transformer fine-tune" → N=5·10·20 모델 하나, 이슈당 4궤적, 스텝당 토큰 예산, B1은 late fusion (§3 모델, 2026-11-09)
- **제안서:** M3 = Transformer fine-tune (ModernBERT 등), 입력 "앞 N스텝 원문". N 6개 전체가 대상이다 (§3 표, §5 N 그리드)
- **수정 후:** ModernBERT-base(revision 고정) 하나가 N ∈ {5, 10, 20}을 맡는다. epoch마다 N별 이슈당 최대 4궤적을 새로 뽑아 학습한다. 입력은 스텝마다 생각 32 + 명령 24 + 관측 앞 26·뒤 12토큰이다 (N=20도 2,048 안). 이슈 본문은 넣지 않고 B1과는 late fusion으로 결합한 `m3_bert_b1`을 따로 낸다. 하이퍼파라미터는 그리드 없이 고정이다 (PLAN 11절 D7, P7-D1~D5)
- **이유:** 전체 N·전체 궤적으로 학습하면 RTX 5070 12GB에서 5 fold에 10시간을 넘는다 [가정: 처리량 측정으로 추정]. 이슈당 4궤적이면 이슈는 모두 보고 계산량은 약 1/4이다. 개발 실행은 약 4~4.5시간이다 [가정]
- **영향:** M3 결과는 N 3개에서만 보고한다 (나머지 N은 M1·M2만). M1 XGB와 짝지은 비교가 주 비교다 (`results/phase7/paired.csv`). 제안서 예상 "반나절~하루"는 실측으로 갱신한다 (docs/phase7.md 7.4)
- **실측 (2026-11-10 메모):** 개발 약 3시간(fold당 학습 약 31분) + `--final` 약 30분으로 제안서 예상 "반나절~하루" 안이다. 결과는 판별이 M1·M2와 같은 수준이고 비용 절약은 M1보다 적다 (N=20 결합 K\* 대비 스텝 +3.7%p · 토큰 +3.8%p, M1 XGB 대비 −3.6%p · −5.1%p, docs/phase7.md 7.4)

- **제안서:** "8B·405B 궤적(5,244개)은 다른 모델 일반화 테스트로 쓴다" (결과 5번: 70B 같은 모델 테스트 vs 8B·405B 다른 모델 테스트)
- **14번 이후:** 테스트는 70B만이고 8.1은 범위에서 뺐다
- **수정 후:** 주 결과·분할은 그대로 둔다. 70B로 학습한 M1(`m1_xgb`, `m1_lr`)을 8B·405B 궤적에 그대로 적용하는 보조 실험을 둔다 (`code/07_m1_cross.py`, `docs/phase8.md` 8.1). 주 집합은 70B test 이슈의 8B·405B 궤적(707·255개, 이슈 87·22개)이다. 70B train 이슈의 궤적까지 넣은 전체는 참고로 둔다. τ·K·K\*는 70B train에서 고른 값이고, 이 데이터에서는 아무것도 고르지 않는다
- **이유:** 사용자 요청(2026-11-10)이다. 제안서의 "다른 모델 일반화" 질문에 답할 수 있는 데이터가 이미 파싱되어 있다. 테스트 이슈 부분만 주로 써서, 14번이 문제 삼은 "같은 이슈가 학습과 테스트에 모두 들어감"을 피한다
- **영향:** B1 포함 M1은 뺀다 (8B·405B용 B1 fold 점수가 없다). 테스트 이슈 수가 작아 구간이 넓다. 70B 외 결과는 모두 보조 실험으로 확정 (PLAN 11절 P8-D1, 2026-11-10). 발표 위치는 Phase 9에서 정한다

## 용어
- **궤적(trajectory):** 에이전트가 이슈 하나를 처음부터 끝까지 시도한 기록. 같은 이슈를 여러 번 시도해서 궤적 80,036개 / 이슈 3,591개다.
- **스텝:** 에이전트 행동(`ai` 메시지) 1개 + 환경 응답(`user` 메시지) 1개.
- **B0 / B1:** 기준선. B0 = 고정 스텝 상한·에러 횟수 규칙, B1 = 이슈 본문만으로 예측(이슈 난이도 기준선).
- **M1 / M2 / M3:** 제안 모델. M1 = 피처 + XGBoost, M2 = 행동 시퀀스 LSTM, M3 = 원문 Transformer.
- **AUROC:** 실패 궤적 하나와 성공 궤적 하나를 뽑았을 때 실패 쪽에 더 높은 실패 점수를 줄 확률. 0.5 = 무작위, 1.0 = 완벽.
- **이슈 내 AUROC:** 같은 이슈 안의 궤적끼리만 비교한 AUROC. 이슈 난이도 효과를 뺀 궤적 신호의 크기.
- **고정 상한 K:** K스텝을 넘으면 무조건 끊는 규칙. 예측 모델이 이겨야 하는 운영 기준선.
